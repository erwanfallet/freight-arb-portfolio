# Adding a new chain to the portfolio

Template followed by A (iron ore), B (coal), C (products). A new chain — agriculture,
LNG, or otherwise — always touches the same seven files, in this order.

## 0. Before writing a line of code

Find the **unit trap** — that's the real subject of every project in this portfolio, not
an extra technical detail:

| Project | Quoted unit | Economic unit |
|---|---|---|
| A | dry tonne (dmt) | wet tonne (wmt), the one freight pays on |
| B | tonne, 6000 kcal reference | the cargo's real kcal |
| C | gallon (US leg) | tonne (EU leg), via a density |

Without a trap of this kind, there's no project — just an arb a practitioner already
knows about. Also check that an **official, free physical-flow series** exists to
validate the thesis (customs, EIA, Eurostat, GACC...): that's what distinguishes "the arb
looks open" from "the cargo actually left," the portfolio's throughline.

## 1. `src/freight/chains/<id>.py` — the engine

A header docstring is mandatory, structured like `ironore.py`/`coal.py`/`products.py`:
- `THESIS` — the claim in 3-5 lines, with the central mathematical identity
- the unit trap, made explicit
- `ASSUMPTIONS` — each parameter named `<LETTER>-H<n>` (e.g. `D-H1`), with its default
  value and, if the bias has a known sign, which one

Pure functions, testable without I/O: decomposition, decisive test, sensitivities.

## 2. `src/freight/ingest/fixture_<id>.py` — the synthetic generator

A hand-built dataset that **imposes** the phenomenon the thesis predicts (not just
plausible noise) — like project B's 2022 break. Tickers prefixed `SYNTH_`. This is what
lets the dashboard run before any real data exists.

## 3. `tests/test_<id>.py` — the golden tests

Every expected value hand-computed in the comment preceding it, never generated by the
code itself and read back after the fact. At least one test that carries the project's
central argument (see the three examples cited in `README.md`, "Test status" section).

## 4. `app/pages/N_<Name>.py` — the dashboard

Numbering follows the order of appearance in `src/freight/portfolio.py`. Six sections,
the S1-S6 template from the three existing pages: current state, term-by-term
decomposition, the decisive test, flow validation, a secondary angle, sensitivities.
Empty `REAL_TICKERS` at the top of the file — as long as it's empty, the page runs on
synthetic data.

## 5. `scripts/smoke_<id>.py`

Runs the full pipeline on the synthetic dataset, without Streamlit — serves as a quick
check and as `make smoke`.

## 6. `data_dictionary.csv`

One row per series, `verified=no` until a ticker has been seen on a terminal. No
Bloomberg ticker gets written in without having been confirmed via `CTM` then `DES`.

## 7. `src/freight/portfolio.py`

The only place that makes the project appear on the home page. Add a `Project` with
`status=STATUS_READY`, the golden-test count, and the dashboard path — `app/Home.py`
needs no other change.

---

and LNG — as a reminder of what's left to scope before coding: the thesis in five lines,
